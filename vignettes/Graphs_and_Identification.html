Graphs and Identification

This vignette introduces the ADMG graph layer and the identify() function. It uses small canonical ADMG examples to show how graph structure drives identification.

The central idea is that a graph is not just a picture. It is a compact statement of the causal assumptions under which an interventional quantity, such as E[Y(a)] or E[Y(1)-Y(0)], can be written in terms of the observed data distribution. identify() takes an ADMG, a treatment, and an outcome, and asks whether the package knows such a translation. If it does, estimation can proceed; if it does not, the data alone do not justify the requested effect under the graph.

Constructing an ADMG

An acyclic directed mixed graph (ADMG) has two edge types:

  • Directed A → B: A causally affects B.
  • Bidirected A ↔︎ B: A and B share an unmeasured common cause.

“Acyclic” means that following directed arrows never brings you back to the same variable. “Mixed” means that the graph contains both directed and bidirected edges. ADMGs are useful because they let us represent hidden variables without drawing them explicitly: instead of adding an unobserved U with U -> A and U -> Y, we draw A <-> Y.

This distinction matters for identification. A directed path from A to Y is a possible causal pathway. A bidirected path is a warning that some association is due to latent common causes. Identification is about separating the directed causal part from the associational part using the structure of the graph.

# Frontdoor graph: A → M → Y, A ↔ Y (hidden U affects both A and Y)
g_fd = make_graph(
    vertices = [:A, :M, :Y],
    di_edges  = [(:A, :M), (:M, :Y)],
    bi_edges  = [(:A, :Y)],
)
ADMG([:A, :M, :Y], [(:A, :M), (:M, :Y)], [(:A, :Y)], Dict{Symbol, Vector{Symbol}}(), Dict{Symbol, Bool}(:M => 0, :A => 0, :Y => 0))
println("```{mermaid}")
println(to_mermaid(g_fd; direction="LR"))
println("```")

# Backdoor graph: X → A → Y, X → Y  (X is an observed confounder)
g_bd = make_graph(
    vertices = [:X, :A, :Y],
    di_edges  = [(:X, :A), (:X, :Y), (:A, :Y)],
)

Graph Properties

Graph properties are the vocabulary used by identification algorithms. Parents and children describe direct arrows. Ancestors and descendants describe all directed upstream or downstream variables. Districts describe latent confounding. Markov blankets and Markov pillows are local adjustment sets used by the estimators.

Parents, children, descendants, ancestors

println("parents(:M)     = ", parents(g_fd, :M))
println("children(:A)    = ", children(g_fd, :A))
println("descendants(:A) = ", descendants(g_fd, [:A]))
println("ancestors(:Y)   = ", ancestors(g_fd, [:Y]))
parents(:M)     = [:A]
children(:A)    = [:M]
descendants(:A) = [:A, :M, :Y]
ancestors(:Y)   = [:Y, :M, :A]

Districts (bidirected-connected components)

The district of a vertex is the set of vertices reachable by bidirected paths — encoding which variables share hidden common causes.

println("district(:A) in frontdoor = ", district(g_fd, :A))
println("district(:M) in frontdoor = ", district(g_fd, :M))

println("\nAll districts in frontdoor graph:")
for d in all_districts(g_fd)
    println("  ", d)
end

Reachable closure

The reachable closure of a set S is the smallest superset of S such that every vertex outside it is sequentially a-fixable. It is the core operation underlying One-Line ID.

rc = reachable_closure(g_fd, [:Y])
println("Reachable closure of {Y}: ", rc.reachable_closure)
println("Fixing order:              ", rc.fixing_order)
Reachable closure of {Y}: [:Y]
Fixing order:              [:M, :A]

Fixability and General ID

Three fixability conditions determine which estimator is available:

Condition Check Estimator
a-fixable (backdoor) desc(A) ∩ dist(A) = {A} Backdoor TMLE
p-fixable (front-door) dist(A) ∩ ch(A) = {} NPS-TMLE
nested-fixable One-Line ID passes ANIPW

These conditions are graph-theoretic versions of familiar identification arguments:

  • a-fixable covers backdoor-style identification. After removing incoming arrows into the treatment, the treatment is not in the same hidden-confounding district as any of its descendants. The effect can be estimated by adjusting for the treatment’s Markov pillow.
  • p-fixable covers front-door and related primal-fixable/NPS settings. The treatment may be confounded with the outcome, but none of its children are in the treatment’s hidden-confounding district. This allows the effect to be recovered through post-treatment variables without conditioning away the causal pathway.
  • nested-fixable covers harder ADMGs where neither simple adjustment nor p-fixability is enough, but a One-Line ID style fixing sequence still identifies the interventional distribution.

There is also a more general symbolic check: ID_algorithm(g, treatment, outcome) runs the Pearl-Shpitser ID algorithm. This can identify ADMG effects even when the result is not one of the estimator classes above. In that case identify() reports :id_algorithm, which means the identifying functional is known but estimate_causal() does not yet have an automatic estimator for that arbitrary functional.

If all checks fail, the package reports :not_identified. For the general ID algorithm this comes with a hedge witness: two bidirected-connected structures that show why the effect cannot be recovered from the observed law in the given ADMG.

A small a-fixability example

In the backdoor graph, A has one descendant, Y. The treatment district is just {A} because there are no bidirected edges involving A. Therefore desc(A) ∩ dist(A) = {A}, which is the a-fixability condition. The Markov pillow is the observed confounder X, so the package adjusts for X.

println("descendants(A): ", descendants(g_bd, [:A]))
println("district(A):    ", district(g_bd, :A))
println("Markov pillow:  ", markov_pillow(g_bd, :A; treatment=:A))
descendants(A): [:A, :Y]
district(A):    [:A]
Markov pillow:  [:X]

In the bow graph below, A and Y are in the same district because of A <-> Y, and Y is also a descendant of A. The hidden confounding and the direct causal effect are entangled, so the package does not identify the effect.

println("  is_p_fix(:A) = ", is_p_fix(g_fd, :A))

Identification with identify()

identify() checks all three conditions in order and returns the routing strategy plus any metadata the estimator needs.

The order is practical. If a graph is a-fixable, the package can use the standard backdoor estimators. If not, it checks p-fixability and routes to the front-door/NPS estimators. If that also fails, it tries the nested-fixable route. Finally, it runs the general ID algorithm. The returned strategy is therefore an estimation instruction when it is :a_fixable, :p_fixable, or :nested_fixable, and a symbolic identification result when it is :id_algorithm.

id_bd = identify(g_bd, :A, :Y)
println("Backdoor:  ", id_bd.strategy)

id_fd = identify(g_fd, :A, :Y)
println("Frontdoor: ", id_fd.strategy)
Backdoor:  a_fixable
Frontdoor: p_fixable

Non-identified: the bow graph

The bow graph (A → Y, A ↔︎ Y) is the classic non-identified case. The direct effect and the hidden confounder cannot be disentangled.

g_bow = make_graph(
    vertices = [:A, :Y],
    di_edges  = [(:A, :Y)],
    bi_edges  = [(:A, :Y)],
)
println("Bow graph: ", identify(g_bow, :A, :Y).strategy)
Bow graph: not_identified

General ID algorithm

ID_algorithm() is useful when we want to separate mathematical identification from currently implemented estimators. On the front-door graph, it recovers the familiar front-door functional. On the bow graph, it fails and returns a hedge.

id_general = ID_algorithm(g_fd, :A, :Y)
println("front-door identified by ID: ", id_general.identified)
println("front-door functional:       ", id_general.expression)

id_bow = ID_algorithm(g_bow, :A, :Y)
println("bow identified by ID:        ", id_bow.identified)
println("bow hedge:                   ", id_bow.hedge)
front-door identified by ID: true
front-door functional:       sum_{M} P(M | A) * sum_{A} P(A) * P(Y | A, M)
bow identified by ID:        false
bow hedge:                   (S = [:Y], F = [:A, :Y], treatment = [:A], outcome = [:Y])

Nested-fixable: the extended front-door

When dist(A) and ch(A) overlap — i.e., A shares hidden common causes with one of its children — p-fixable fails. The One-Line ID algorithm can still identify the effect in more complex graphs. identify() checks this automatically.

# Extended front-door: Z→A→M→Y, A↔M, Z→Y
# dist(A) = {A,M}  (A↔M bidirected), ch(A) = {M}  → NOT p-fixable
# But still identified by One-Line ID
g_ext = make_graph(
    vertices = [:Z, :A, :M, :Y],
    di_edges  = [(:Z, :A), (:Z, :Y), (:A, :M), (:M, :Y)],
    bi_edges  = [(:A, :M)],
)

id_ext = identify(g_ext, :A, :Y)
println("is_p_fix(:A) = ", is_p_fix(g_ext, :A))
println("strategy     = ", id_ext.strategy)
if id_ext.strategy == :nested_fixable
    println("Y*: ", id_ext.ystar)
end
is_p_fix(:A) = false
strategy     = not_identified
