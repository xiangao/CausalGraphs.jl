Nested-Fixable Estimation and Missing Data

This vignette covers two situations where simple backdoor and front-door workflows are not enough:

  1. nested-fixable effects in ADMGs with more complicated hidden-confounding structure;
  2. missing-data weighting using missingness DAGs (mDAGs).

The common theme is identification before estimation. The graph determines whether the target law can be represented using observed data. Only after that step does the package construct weights and nuisance regressions.

Part 1: Nested-Fixable Estimation (ANIPW)

The identification hierarchy

a-fixable  ⊂  p-fixable  ⊂  nested-fixable  ⊂  identified

A treatment is nested-fixable when the effect is identified by the One-Line ID algorithm, but is neither a-fixable nor p-fixable. This occurs when a child of the treatment shares a hidden common cause with the treatment — so neither backdoor nor front-door adjustment is sufficient.

The word “nested” comes from nested Markov models for ADMGs. In these models, identification is described by repeatedly “fixing” variables: moving a variable from random to fixed status and updating the kernel that describes the remaining random variables. If a valid fixing sequence isolates the target counterfactual distribution, the effect is identified even though no ordinary adjustment set or classical front-door formula exists.

Operationally, identify() uses a One-Line ID style check. If it passes, estimate_causal() routes to nested IPW estimators. These estimators construct rebalancing weights associated with the intrinsic kernels of the relevant districts. ANIPW augments those weights with outcome regression terms, in the same spirit that AIPW augments ordinary IPW.

Example: HIV treatment graph

A drug treatment T affects CD4 count (outcome), mediated partly through Toxicity and Adherence. Hidden common causes link several variables.

This is the kind of example where nested-fixability matters. Backdoor adjustment is not enough because hidden common causes connect treatment-related variables. Classical front-door is not enough because a child of treatment, Toxicity, lies in the same district as treatment. But the graph still has enough structure for a valid fixing sequence: the outcome-relevant part of the graph can be isolated after repeatedly fixing variables outside the target kernel.

Simulate data from the DGP

function sim_hiv(n; seed=42)
    Random.seed!(seed)
    # Latent hidden common causes
    U_EI   = randn(n)   # Exercise ↔ Income
    U_ET   = randn(n)   # Exercise ↔ T
    U_ITox = randn(n)   # Income ↔ Toxicity
    U_VA   = randn(n)   # ViralLoad ↔ Adherence
    U_VCD4 = randn(n)   # ViralLoad ↔ CD4

    ViralLoad = randn(n)
    Exercise  = randn(n) .+ 0.5 .* U_EI .+ 0.5 .* U_ET
    Income    = randn(n) .+ 0.4 .* ViralLoad .+ 0.4 .* U_EI .+ 0.4 .* U_ITox
    T         = Float64.(rand(n) .< logistic.(0.5 .* ViralLoad .+ 0.3 .* Income .+ 0.4 .* U_ET))
    Toxicity  = randn(n) .+ 0.6 .* T .+ 0.3 .* U_ITox
    Adherence = randn(n) .+ 0.5 .* Toxicity .+ 0.3 .* U_VA
    CD4       = randn(n) .+ 0.4 .* T .+ 0.3 .* Adherence .+
                            0.2 .* Exercise .+ 0.3 .* ViralLoad .+
                            0.3 .* U_VCD4 .+ 0.2 .* U_VA

    # True ACE(T=1 vs T=0):
    # Direct: 0.4
    # Indirect T→Tox→Adh→CD4: 0.6 × 0.5 × 0.3 = 0.09
    # Total ≈ 0.49

    DataFrame(ViralLoad=ViralLoad, Income=Income, Exercise=Exercise,
              T=T, Toxicity=Toxicity, Adherence=Adherence, CD4=CD4)
end

df_hiv = sim_hiv(2_000)

Nested rebalancing weights

The ANIPW estimator builds nested rebalancing weights through the intrinsic kernel of each modified district. After reweighting, propensity and outcome regression are estimated by weighted GLM.

The practical interpretation is similar to ordinary IPW but with more graph structure. Ordinary IPW balances treatment groups with respect to measured confounders. Nested rebalancing weights balance the pieces of the observed law that appear in the nested identification formula. This is why nested-fixable estimation is available even when neither a single adjustment set nor a front-door mediator formula is valid.

rw = res_hiv[:rw]
@printf("Rebalancing weights — min: %.3f  max: %.3f  mean: %.3f\n",
        minimum(rw), maximum(rw), mean(rw))

Part 2: Missing Data with mDAGs

When covariates are missing at random (MAR), CausalGraphs.jl identifies and estimates the missing-data propensity scores, producing per-row IPW weights for estimate_causal().

An mDAG extends a causal graph with missingness indicators. A variable such as X has an indicator R_X showing whether X is observed. Edges into R_X encode the missingness mechanism. For example, T -> R_X says treatment status affects whether X is observed; X -> R_X says missingness depends on the value of X itself.

The key identification question is whether the target full-data law can be recovered from the observed-data law. If the missingness process is recoverable, the package estimates observation probabilities and forms inverse probability weights. Those weights can then be passed to the causal estimator, so the causal analysis is performed on complete cases weighted back toward the target population.

This separates two assumptions:

  • the causal ADMG says how treatment, outcome, and covariates relate;
  • the mDAG says how values become missing.

Both matter. A causal effect may be identified with complete data but not recoverable under a given missingness graph.

For a simple MAR graph, suppose X is sometimes missing and the probability of observing X depends on fully observed variables A and Y, but not on the unobserved value of X after conditioning on them. Then complete cases can be weighted by 1 / P(R_X=1 | A, Y) to recover full-data averages. If instead X -> R_X is present and no other structure helps, complete cases can be systematically different in a way that ordinary complete-case analysis and simple MAR weighting cannot repair.

Workflow

# 1. Define the missingness DAG (mDAG)
mdag = make_mdag(
    obs_variables      = ["T", "CD4"],
    missing_variables  = ["ViralLoad"],
    missing_indicators = ["R_VL"],
    di_edges = [("ViralLoad","T"), ("ViralLoad","CD4"), ("ViralLoad","R_VL"),
                ("T","CD4")],
)

# 2. Identify and estimate missing-data propensities
ID    = ID_algorithm(mdag)
props = propensity(mdag, data_with_missing, ID; law=:target)

# 3. Build IPW weights on complete cases
obs = .!ismissing.(data_with_missing.ViralLoad)
wts = 1.0 ./ coalesce.(props["R_VL"].pred[obs], 1.0)

# 4. Estimate causal effect using IPW-weighted complete cases
result = estimate_causal(
    a=[1,0], data=dropmissing(data_with_missing),
    graph=g_hiv, treatment=:T, outcome=:CD4,
    sample_weights=wts,
)
